# Семейные финансы

Адаптивное PWA для общего учёта финансов семьи. Согласованные функции описаны в [PRODUCT_SPEC.md](PRODUCT_SPEC.md), схема разработки — в [ARCHITECTURE.md](ARCHITECTURE.md), порядок работ — в [BACKLOG.md](BACKLOG.md).

## Облачное приложение

Основной адрес: [family-finance-tracker.family-finance-tracker.workers.dev](https://family-finance-tracker.family-finance-tracker.workers.dev/). Он открывается по HTTPS на компьютере и телефонах. Основная D1 уже создана и миграции применены; семейный профиль в ней ещё не создан. Для первого входа укажите свой email, пароль от 12 символов и ключ `ACCOUNT_SETUP_KEY` из локального `.dev.vars`. Не отправляйте этот ключ вместе с ссылкой на приложение. После создания профиля на втором телефоне нужен только общий email и пароль.

Отдельные Worker и D1 `family-finance-tracker-staging` предназначены для пробных операций. В них проверены создание профиля, вход и откат D1 Time Travel с последующим восстановлением прежнего состояния. Семейные данные в тестовую среду не вносите. Для повторного размещения основной версии после проверки изменений используйте `pnpm deploy`; секреты уже настроены в Cloudflare и не хранятся в Git.

## Локальный запуск

Нужны Node.js и pnpm.

```powershell
pnpm install
if (!(Test-Path .dev.vars)) { Copy-Item .dev.vars.example .dev.vars }
pnpm db:migrate:local
pnpm dev
```

Перед запуском замените оба значения в `.dev.vars` на две разные случайные строки длиной не менее 32 символов. Если файл уже существует, сохраните его: повторно копировать шаблон не нужно. Ключ `ACCOUNT_SETUP_KEY` понадобится в форме однократного создания профиля. Не публикуйте `.dev.vars` в репозитории.

Пока команда работает в терминале, откройте `http://127.0.0.1:5173/`. При закрытии терминала локальный сайт остановится. Локальный Worker отвечает на `GET /api/health`.

## Проверка сборки

```powershell
pnpm check
pnpm build
pnpm preview
```

При первом открытии создайте один общий профиль по email, паролю и ключу первого запуска. На втором устройстве используйте тот же email и пароль. После входа приложение предложит ввести стартовый остаток карты. В истории можно выбрать месяц, посмотреть доходы и расходы, разбивку по категориям, исправить или удалить запись. На экране «Цели» можно создать цель, выделить на неё деньги и вернуть их в свободную сумму; расход из цели выбирается в дополнительных полях записи. Финансовые данные сохраняются на устройстве и после подключения отправляются в общий профиль D1. На втором устройстве войдите под тем же профилем; данные загрузятся автоматически. Если оба устройства исправили одну запись, приложение предложит выбрать общую или локальную версию. В «Настройках» можно скачать резервную копию после синхронизации. Дальнейшие этапы перечислены в `BACKLOG.md`. Команда `pnpm deploy` предназначена для будущего развёртывания после настройки Cloudflare и проверки приложения.

## Резервная копия и восстановление

В «Настройках» нажмите «Скачать резервную копию». Приложение сначала отправит записи с этого устройства в D1 и предложит разрешить конфликты, если они есть. Файл `family-finance-ГГГГ-ММ-ДД.json` содержит все строки финансовых таблиц и журнала синхронизации для общего профиля, включая архивные и удалённые записи. Пароли и сессии в файл не входят. JSON храните в закрытом месте: в нём есть ваши суммы и заметки. Автоматического импорта этого файла через приложение пока нет.

Администратор может проверить текущую точку восстановления командой `pnpm exec wrangler d1 time-travel info family-finance-tracker`. Для отката к моменту в пределах срока хранения используйте `pnpm exec wrangler d1 time-travel restore family-finance-tracker --timestamp="2026-09-28T12:00:00Z"`, заменив дату на нужную. Команда перезаписывает всю базу; перед ней сохраните свежую JSON-копию и текущую закладку, которую покажет `time-travel info`. Команда отката выведет закладку прежнего состояния для отмены отката через `--bookmark=...`. Срок хранения: 7 дней на Workers Free, 30 дней на Workers Paid. Эти команды действуют только на удалённую D1; пробный откат и его отмена проверены на отдельной тестовой базе.

## Проверка на двух iPhone

После размещения приложения по HTTPS откройте его в Safari на каждом телефоне. Через «Поделиться» выберите «На экран Домой», включите «Открыть как веб-приложение» и добавьте значок. Запускайте приложение именно через значок. [Инструкция Apple](https://support.apple.com/guide/iphone/open-as-web-app-iphea86e5236/27/ios/27).

1. Войдите в общий профиль на обоих телефонах и дождитесь надписи «Все изменения синхронизированы».
2. На первом телефоне отключите сеть, закройте приложение, снова откройте его через значок и добавьте пробный расход с узнаваемой заметкой. Он должен остаться в истории после повторного открытия, а приложение должно показать ожидающее изменение.
3. Включите сеть на первом телефоне и дождитесь завершения синхронизации. Откройте приложение на втором телефоне: расход должен появиться без дубля и с той же суммой и датой.
4. Повторите шаги 2–3 в обратном направлении. Затем исправьте одну и ту же пробную запись на обоих телефонах без сети и проверьте, что приложение предлагает выбрать версию после подключения.
5. Удалите пробные записи и проверьте, что удаление появилось на втором телефоне.

До проверки на физических iPhone мобильная эмуляция Chrome подтвердила управление приложением service worker, открытие без сети, сохранность расхода после повторного открытия и появление записи на втором независимом устройстве после синхронизации. Поведение Safari и добавление значка на экран Домой этой проверкой не подтверждены.

## Локальная база D1

Схема финансовых данных находится в [migrations/0001_initial.sql](migrations/0001_initial.sql), схема Better Auth — в [migrations/0002_better_auth.sql](migrations/0002_better_auth.sql). Примените обе миграции к локальной D1 и проверьте статус:

```powershell
pnpm db:migrate:local
pnpm db:status:local
```

Локальная D1 хранится в `.wrangler/state`. Она содержит общий профиль, сессии и синхронизированные финансовые записи. Данные, внесённые до подключения синхронизации, ставятся в очередь при обновлении локальной базы; если стартовый остаток на сервере уже отличается, приложение попросит выбрать версию. Удалённые основная и тестовая D1 указаны в `wrangler.jsonc`. Миграции для основной базы применялись с `--remote`, для тестовой — с `--remote --env staging`. Не путайте локальную и удалённые базы при проверке изменений.

## Рабочий процесс

- Все задачи и дальнейшие запланированные действия записываем в [BACKLOG.md](BACKLOG.md) до завершения текущей работы.
- Каждая задача получает уникальный постоянный номер `FT-1`, `FT-2` и так далее. Новую задачу нумеруем следующим свободным номером; удалённые номера не используем повторно.
- Для каждой задачи фиксируем статус, описание, дату появления в формате `ГГГГ-ММ-ДД` и короткое пояснение, как она появилась (например, запрос пользователя, решение при проектировании или найденная ошибка).
- Статусы: `Запланировано`, `В работе`, `Готово`, `Заблокировано`. При начале и завершении работы обновляем статус существующей задачи. Если меняется объём работы, правим её описание; одинаковые задачи не дублируем.
- Дата появления остаётся датой первой записи задачи в плане. Для задач, перенесённых из исходного списка, это дата создания `BACKLOG.md`.
