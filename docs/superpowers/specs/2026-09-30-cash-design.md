# Наличные (FT-21)

Дата: 2026-09-30. Запрос пользователя: добавить учёт наличных. Решения пользователя: отдельный общий кошелёк наличных; переводы между картой и наличными; наличные входят в «Свободно» и в деньги для целей; стартовый остаток наличных спрашивается карточкой на главной и правится в настройках; счёт выбирается переключателем в быстром вводе и запоминается; перевод — третий тип в быстром вводе; в истории фильтр по счёту и переводам.

## Модель

- `Account = "card" | "cash"`. Доход и расход получают `account`; запись без поля считается картой.
- `Transfer`: `id`, `from` (`card` или `cash`, получатель — другой счёт), `amountKopeks > 0`, `occurredAt`, `createdAt`, `author`, `note`, `deletedAt`, `version`. Не доход и не расход, не входит в отчёты по категориям.
- `Settings.openingCashKopeks: number | null`; `null` — стартовые наличные ещё не указаны.

## Расчёты

- Карта = стартовый капитал + доходы − расходы по карте − переводы с карты + переводы на карту.
- Наличные = стартовые наличные (0, если не указаны) + доходы − расходы наличными − переводы из наличных + переводы в наличные.
- Свободно = карта + наличные − выделено на цели. Расход из цели можно оплатить любым счётом.
- Отрицательные остатки показываются, но не блокируют запись.

## D1 и воркер

- Миграция `0003_cash.sql`: `transactions.account TEXT NOT NULL DEFAULT 'card'` с проверкой значения; `settings.opening_cash_kopeks INTEGER` (NULL или ≥ 0); таблица `transfers`; пересоздание `change_log` с сохранением `seq`, чтобы тип сущности допускал `transfer`.
- Синхронизация: вид изменения `transfer` с версиями и мягким удалением; `/api/bootstrap` отдаёт `transfers`; изменение настроек без `openingCashKopeks` сохраняет прежнее значение; свободная сумма на сервере учитывает наличные. Выгрузка JSON включает `transfers`.

## Клиент

- IndexedDB версии 4 с хранилищем `transfers`.
- Мутации `saveTransfer`, `updateTransfer`, `deleteTransfer`, `saveOpeningCash`; атом `$lastAccount` (localStorage) запоминает счёт быстрого ввода.

## Интерфейс

- Баланс: «Свободно», под ним «На карте», «Наличные», «В целях».
- Виджет «Сколько сейчас наличных?» на главной, пока `openingCashKopeks === null`.
- Быстрый ввод: «Расход / Доход / Перевод»; для дохода и расхода переключатель «Карта / Наличные»; для перевода — направление вместо категорий, в «Дополнительно» дата, автор и заметка.
- «Последние записи» и история включают переводы. История: фильтры «Все / Расходы / Доходы / Переводы» и «Все счета / Карта / Наличные»; строка показывает счёт; итоги месяца учитывают выбранный счёт; перевод исправляется в шторке и удаляется с подтверждением.
- Настройки: раздел «Наличные» со стартовым остатком и кнопкой «Изменить».
- Первый шаг нового профиля спрашивает остаток карты и наличных.
- Скелетоны изменённых виджетов совпадают с контентом до пикселя.

## Проверка

- Тесты расчётов и схемы D1, `pnpm check`, `pnpm build`, ручной прогон в браузере с локальной D1, сверка скелетонов.
- Перед размещением миграция применяется к тестовой, затем к основной удалённой D1 — только после подтверждения пользователя.
